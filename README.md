# UX_LabelShop 桌面客户端（.NET 8 / WPF）

内网标签打印系统客户端：直连 MySQL，单文件 exe，无需服务端与打印代理。

## 已实现功能

| 模块 | 状态 |
|---|---|
| 登录 + 两级权限（用户/管理员） | ✅ 工号密码、BCrypt、首次登录强制改密、管理员可重置密码/停用、**支持「记住密码」（DPAPI 当前用户加密本机保存）** |

| 扫码打印 | ✅ 模板选择、扫码规则解析、清单编辑、**Ctrl+点击列标题向下填充空白格**、固定值/序列号/复制上行批量填充、行级实时预览 |

**复制模板**：对话框里填的新名称/编码会同时写进 `label_template` 表和**版本 content 快照**里的 `name`/`id`。
早期版本只照抄了源模板的 content，导致副本在编辑器里显示旧名字，一保存还会把表名改回旧值。
现在 `LoadDoc` 一律以 `label_template` 表的 `name`/`code` 为准覆盖 content 里的同名字段，
因此已经存在的旧副本重新打开也会显示正确名称（下次保存即把快照一并修正）。

**两套工具栏**：模板管理页（模板 / 配置 / 状态）与模板编辑器（添加 / 层级 / 操作）都用竖线分组、组名小字标注、
按钮带 16×16 矢量图标；图标与 `ToolButton` / `PrimaryToolButton` / `DangerToolButton` / `GroupLabel` / `ToolSep`
样式统一定义在 `App.xaml`，两处共享、不重复。蓝色为主操作（新建模板 / 发布 / 保存），红色为危险操作（删除草稿）。
图标是 `Geometry` 路径数据，不依赖任何图标字体或图片文件。

## 运行

```bash
cd client/UXLabelshop
dotnet build
dotnet run --project UXLabelshop.csproj
```

首次启动会引导「数据库设置」，连接信息保存在 exe 同目录 `config.json`（密码经 DPAPI 当前用户加密）。

开发期可用环境变量覆盖数据库密码：`UX_DB_PASSWORD=...`。

```bash
cd client/UXLabelshop
dotnet publish -c Release -o ../publish
```

产物：`client/publish/UXLabelshop.exe`（约 74MB，自包含，Win11 免装运行时）。
配置文件 `config.json` 首次运行时生成在 exe 同目录，日志在 `logs/`。

## 客户端自升级

**服务器上只有目录和 exe，没有清单文件、没有脚本、没有应用层改动。** nginx 的 `autoindex` 目录列表本身就是版本清单。

### 服务器一次性配置

```nginx
location /client-update/ {
    alias /var/www/labelshop-update/;
    autoindex on;
    # autoindex_format json;          # 可选，不写也能用（默认 HTML）
    # allow 192.168.1.0/24; deny all; # 可选，改成实际内网网段
}
```

```bash
sudo mkdir -p /var/www/labelshop-update
sudo nginx -t && sudo systemctl reload nginx
```

### 发布（不需要脚本）

1. `dotnet publish -c Release -p:Version=0.2.0 -o ../publish`
2. 把 `UXLabelshop.exe` 改名为 **`UXLabelshop_v0.2.0.exe`**（三段纯数字，不要 `beta`/日期等后缀）
3. 丢进 `/var/www/labelshop-update/`

客户端把目录列表当纯文本用正则扫 `UXLabelshop_vX.Y.Z.exe`，按数字段取最高版本，所以 HTML / JSON 格式都能解析。
目录里可留多个历史版本；**移走高版本文件即对尚未升级的机器回滚**，已升级的机器用同目录 `.exe.old` 改回文件名，或发 `0.2.1`。

### 客户端配置

升级地址**可配置**，两处都行（优先级相同，都是写 `config.json` 的 `UpdateUrl`）：

- 登录页「数据库 / 本机设置」→ 底部「客户端升级地址（可选）」，例如 `http://192.168.1.35/client-update/`
- 或直接编辑 exe 同目录 `config.json`：`"UpdateUrl": "http://192.168.1.35/client-update/"`

**留空 = 完全不检查更新**（默认），所以服务器没配好之前客户端照常使用，不会有任何网络请求或报错。

### 行为

- 只在**启动时异步查一次**，3 秒超时、失败静默，绝不阻塞开机；顶栏「检查更新」可手动触发。
- 发现新版只弹一条黄色提示条（版本 / 文件名 + 立即更新 / 稍后），**不强制、不灰度、不自动下载**。
- 点「立即更新」：若清单有未打印行先警告 → 下载到同目录 `<当前exe名>.new` → 用 `Content-Length` + PE 头 `MZ` 校验 → 确认重启 → 生成临时 PowerShell 脚本，等旧进程退出后把旧 exe 改名 `.exe.old`、新文件改成正式名、启动新进程。
- exe 在桌面 / 文档 / D 盘等用户可写目录，全程**不需要管理员**；`config.json` 和 `logs/` 不动，DPAPI 密码不丢。`.exe.old` 会一直保留，人工可回滚。
- 自检：`vartest` 覆盖目录解析（JSON/HTML）、版本比较、URL 拼接、未配置时关闭检查、非 PE 文件拒绝；`uicheck` 生成 `12-update-banner.png` 提示条快照。

## 数据库

服务器 `192.168.1.35`，库 `ux_labelshop`（表前缀 `label_` / `sys_`）。

| 表 | 说明 |
|---|---|
| `sys_user` | 客户端用户（role: user/admin） |
| `label_template` / `label_template_ver` | 模板主表 + 版本快照（画布 + 内嵌变量快照，保存即新版本） |
| **`label_template_var`** | **模板变量定义子表（唯一权威来源）**：`template_id / var_key / label / short / source / default_value / formula / sample / value / sort_no / extra_json` |
| `label_scan_rule` | 扫码规则（delimited / regex，沿用原有 7 条规则） |
| `label_print_record` / `label_print_record_item` | 打印记录 + 明细（每行=1 张），记录内含模板快照 |
| `label_field_dict` | 历史字段字典（暂未使用，保留） |

**变量为什么单独成表**：可用 SQL 直接查询/批量修改/逐条排查，不必解剖 JSON；改 Key 会自动级联替换画布 `{{旧}}`、扫码规则映射和其他变量公式里的引用。

- `source` 三值：`scan` 扫码录入 / `fixed` 固定值（不进清单，渲染自动补）/ `computed` 公式计算。
- `default_value`：scan 变量为空时套用；`formula`：以 `=` 开头的 Excel 风格公式。
- `extra_json`：原模板 JSON 里未纳入子表的字段（如 `required`），迁移时保留不丢。
- 首次启动一次性把旧 `content.variables` 迁到子表（`config.json` 的 `VarMigrationDone` 标记），已有变量行的模板不会被覆盖。
- **版本快照 / 打印快照仍内嵌完整变量**，重打旧单不受后续变量修改影响。

## 变量与公式

从「模板管理 → 变量管理」或模板编辑器里的「变量管理…」打开独立窗口，可新增、编辑、删除、上下移；双击行编辑。删除前会列出该变量被引用的位置；改 Key 会级联替换画布正文、扫码规则映射与其他公式里的引用，并生成一个新版本。

**公式语法**（自研解析器，白名单函数，不 eval、不执行任意代码）：

- 变量引用 `{{part_no}}`，字符串 `"..."`，数字，`&` 连接，`= <> < > <= >=` 比较，`+ - * /` 四则
- 文本：`LEFT` `RIGHT` `MID` `LEN` `FIND` `SEARCH` `SUBSTITUTE` `REPLACE` `TRIM` `UPPER` `LOWER` `CONCAT` `TEXTJOIN` `SPLIT`
- 逻辑：`IF` `IFERROR` `AND` `OR` `NOT` `ISBLANK` `ISNUMBER`
- 数值：`ROUND` `INT` `ABS` `VALUE`
- 查库：`DBLOOKUP(查询语句 [, 找不到时的默认值])`

变量对话框带「插入函数 / 插入变量 / 测试公式」，可填测试值当场看结果；管理窗口「校验公式」会检查语法、未知函数、循环依赖与不存在的变量引用。

### 查库公式 DBLOOKUP

```
=DBLOOKUP("SELECT invCoding FROM configproduct WHERE invCode='{{prodno}}'")
```

在标签库（同一个 MySQL）里执行只读查询，返回**结果集首行首列**：

| 情况 | 返回 |
|---|---|
| 查到 1 行 | 该行第 1 列的值（数字/日期按文本输出，整数不带 `.0`） |
| 查不到 | 第二个参数；没写就是**空串**（标签照打，只是缺值） |
| 列为 NULL | 空串 |
| SQL 出错 / 超时 | `#ERR: …`，可用 `IFERROR` 兜底 |

写法要点：

- 公式里的字符串用**双引号**，SQL 内的字面量用**单引号**（Excel 规则）。
- `{{变量}}` 会被改成**参数占位符**，值走驱动参数，不拼字符串，天然免疫注入；变量两侧的引号会自动去掉（`'{{p}}'` → `@p0`）。
- 变量混在字面量中间（如 `LIKE '%{{part_no}}%'`）会自动改写为 `CONCAT('%', @p0, '%')`。
- 公式里出现过的变量自动登记为依赖，清单改那一格会触发本行重算。

安全与性能（`Rendering/SqlGuard.cs` + `Services/SqlLookupService.cs`）：

- 只允许**单条** `SELECT` / `WITH … SELECT`；分号多语句、`INSERT/UPDATE/DELETE/DROP/ALTER/TRUNCATE/CREATE/…`、`INTO OUTFILE`、`SLEEP`、`LOCK` 等一律拒绝。注释和字符串里的同名关键字不算（`WHERE note='DELETE it'` 正常）。
- 连接首次打开后执行 `SET SESSION TRANSACTION READ ONLY`，即使校验被绕过，数据库也会拒绝写入（`transaction_read_only=1`）。
- 单条查询 **5 秒超时**；结果按「SQL + 参数」缓存 **60 秒**（上限 512 条），预览/试打/打印不重复压库。
- 一个模板里的查库公式不宜超过 3~4 个，SQL 建议自己带 `LIMIT 1`。

**两个配置实例**（已在 `ux3320_t` 模板配好，可直接验收）：

| 变量 | 配置 | 效果 |
|---|---|---|
| `bin` | `default_value = BIN1` | 二维码没解析出 BIN 时清单自动填 `BIN1` |
| `part_no2` | `source=computed`，`=IFERROR(SPLIT({{part_no}},"_",1), {{part_no}})` | `part_no=UX3261_D2_H` → 自动算出 `UX3261` |

**计算列行为**：显示在扫码清单里（蓝底 `#BBD4F0` + 表头「· 公式」标记；选中整行时转为更深的 `#1F5FA8` 配白字，保证选中行里也看得清），公式依赖格变动时该行计算列无条件重算；用户也可以手动改计算列的值（两次依赖变动之间保留）。行右键「重算本行公式列 / 重算全部行的公式列」可随时恢复自动值。打印/预览直接用清单当前值，所见即所得。

初始化逻辑在 `Services/DbInitService.cs`：一次性清理旧 B/S 系统表、建新表、种子管理员 `admin / Admin@123`（首次登录强制改密）。

## 扫码规则校准

「模板管理 → 扫码规则」按模板维护解析规则，支持两种类型：

- **分隔符切段（delimited）**：按分隔符拆段 → 去掉首尾空段 → 若设了「首段类型标记」则校验并移除该段 → 按段号取值。
- **正则表达式（regex）**：命名捕获组 + 「组名=变量key」映射。

段号映射是一张**自动生成的表**（段号 / 测试内容 / 对应变量）：

- 填入「测试样例扫码内容」和「分隔符」后立即按样例拆分，段号从 1 自动排序，测试内容就是拆出来的那一段；改样例、改分隔符、改标记都会即时重排。
- **对应变量**列是下拉框，选项来自当前模板的变量（`key（中文名）`），第一项「（不映射）」用于跳过某个段。
- 重排时**已选变量按段号保留**，不会因为改个字就把配好的映射清空。
- 首段标记与样例首段对不上时，表格下方会红字提示「按当前配置不会匹配」。
- 保存时校验：至少映射一个段号；同一变量被多个段号占用会拦下并列出冲突段号。
- **丢失改动前都会确认**：关闭窗口、**切换到另一条规则**、点「新增规则」时，只要当前表单相对上次保存有改动，
  就弹「当前规则「xxx」有未保存的修改，…后会丢失」确认框（默认「取消」）。取消时列表选中项退回原规则、编辑内容原样保留。
  判定用整张表单的状态快照，改回原值不会误报；保存后、程序主动重载列表时自动跳过确认。

## 扫码打印页操作

页面为三段式布局：

- **顶部工具栏**：模板选择、扫码输入框、新增行 / 删行 / 填充… / 清空 / 隐藏预览
- **中部**：左侧清单表格（每行 = 1 张标签），右侧实时预览；中间分隔条可拖动调整预览宽度，「隐藏预览」可整栏收起（表格自动占满）
- **底部状态栏**：左侧为最近一次操作结果（如「已解析（xxx 规则）」「「批号」已向下填充 2 个空白格」），右侧为总张数

表格里每个可编辑列对应模板中的一个变量。

**向下填充空白格**：按住 `Ctrl` 点击列标题，即把该列中每个空白单元格填成它上方最近的非空值（已有值不覆盖；首行上方无值时保持空白）。批量规则填充（固定值 / 序列号 / 递增）用顶部「填充…」按钮。

**表头不支持排序**：清单顺序即为打印顺序，点击列标题不会排序（列绑定的是数据表列名，排序会抛异常，故整体禁用）；带 `Ctrl` 的点击才是填充。

**输入法已禁用**：扫码输入框、清单单元格编辑框、「填充…」对话框全部设了 `InputMethod.IsInputMethodEnabled="False"`。
标签内容只有 ASCII，中文输入法一旦进入候选状态会把扫码枪发来的连续字符吞掉（表现为扫了没反应、或只进去半截）。
注意这个附加属性**不会**从父容器继承到子控件，所以是在扫描框、DataGrid、列编辑样式上分别显式关闭的。

**切换模板会先确认**：清单里已有扫描结果时，换模板会弹警告框说明「当前 N 行结果会被清空」，默认焦点在「取消」；
点取消则模板下拉退回原模板、清单原样保留；点确定才重建列并清空。确认回调由页面注入到 ViewModel
（`ConfirmTemplateSwitch`），自检时换成一个返回 true/false 的假回调，不会弹模态框。
**切换完成后光标自动回到扫码输入框**，不用再点一下就能扫下一张。

**预览实时刷新**：单元格值一变（手输、公式重算、批量填充）就重绘预览，重绘的是**刚被编辑的那一行**，
不再依赖「切换行」触发；清单只有一行、或从未选中过任何行时也能刷新（退回第一行）。
为避免逐字输入时每敲一个键都渲染一次标签，用 120ms 防抖合并；自检模式改为同步刷新便于断言。

**短码补录（PO 号）**：扫码内容 `Trim()` 后长度 **≤20 字符**就视为补录码，不走扫码规则解析：

- 清单为空 → 直接丢弃，状态栏提示「清单为空，请先扫二维码」，**不会**凭空新增一行。
- 有行 → 找当前选中行里**第一个空白的扫码录入字段**（`source=scan`，且未填值），把内容填进去；
  连续扫多个短码会依次填下一个空字段。没选中行时兜底用最后一行。
- 当前行没有空白的 scan 字段 → 丢弃，状态栏提示原因。
- 超过 20 字符才走原来的扫码规则解析并新增一行。

这样二维码里没带 PO 号时，扫完二维码接着扫一下 PO 条码即可补齐；补录不会新增行、也不会把选中行跳到末行。
赋值走 `DataTable.ColumnChanged`，公式列照常重算、预览照常重绘。
注意：**任何 ≤20 字符的码都会被当成补录码**（包括内容较短的二维码），阈值常量是 `ScanPrintViewModel.ShortScanMaxLength`。

预览按面板宽度等比缩放，整张标签一次可见；把分隔条往左拖可放大查看细节。打印预览窗口里，鼠标悬停某张缩略图可看到该张的字段摘要。

## 元素类型

模板画布（`TemplateDoc.elements[]`）支持：

| type | 说明 |
|---|---|
| `text` | 文本，可含 `{{变量}}`，自动缩字号避免溢出 |
| `barcode` | Code128 一维码 |
| `qrcode` | 二维码（`size_mm` 为边长，不含静区） |
| `rect` / `line` | 边框 / 直线（`thickness_mm` 线宽） |
| `image` | 位图（`src` 为路径或 data URI）—— 依赖外部文件，分发时注意 |
| **`symbol`** | **内置矢量符号**，`text` 写符号名（当前 `pb-free`），不依赖图片与字体 |

### 模板编辑器

工具栏按竖线分成 **添加 / 层级 / 操作** 三组，组名用小字标注；每个按钮都带 16×16 矢量图标
（`Window.Resources` 里的 `Geometry` + 统一的 `ToolButton` 模板，不依赖字体或图片文件），
悬停用半透明遮罩反馈，「保存 / 发布」是蓝色主按钮。名称与缩放（含百分比）单独放上一行。
窗口设了 `MinWidth=1080`，保证三组正常排在一行；更窄时会整体换行。

- 点画布上的元素即可选中（橙色框 + 右下角拖拽点），拖动移动、拖拽点缩放（多选时隐藏拖拽点）。
- **多选**：在画布空白处拖出虚线框圈选（命中与框相交的元素）；`Ctrl+点击` 增减单个元素；
  `Ctrl+A` 或工具栏「全选」选中全部；`Ctrl+圈选` 追加命中；点空白处清空选择。
- **多值属性**：选中多个元素时，属性面板里所有元素取值相同的字段显示该值，**取值不同则留空**；
  修改任一字段会把该字段写入全部选中元素，未改动的混合值字段保持各自原值。
  字号/字体等批量设置只作用于选中里的 `text` 元素。批量改属性与批量拖动各**合并为一次撤销**。
- **属性即时生效**：数值/文本在光标离开输入框（或按 Enter）时提交，开关/对齐/下拉点击即提交；
  切换选中元素、保存、试打前会主动提交待生效编辑，不需要「应用修改」按钮。
- **撤销 / 重做**：工具栏「↶ 撤销 / ↷ 重做」，或 `Ctrl+Z` / `Ctrl+Y`（焦点在文本框里时交给文本框自己撤销输入）。
  拖动、缩放、增删元素、上下移层、属性提交都会记一步，最多保留 60 步；纯点击不会污染历史。
- **二维码**按 `size_mm` 画选择框：导入的老模板只有 `size_mm` 没有 `w/h`，
  修复前选择框会退化成 6×6 点、鼠标点不中；现在选中后「宽/高/字号」三格显示同一个边长，改任意一格都生效，拖拽点缩放自动保持正方形。
- 「变量管理…」会重载变量子表，撤销历史随之清空（快照里的变量已过期）。

### Pb 无铅标志

原 `.lsd` 里这个标志是 **`CDrawPicture` 图片对象**（内嵌 LZSS 压缩位图），
旧转换只认文本/条码所以丢了。现在：

- `Services/LsdReader.cs` 扫 `CDrawPicture`，读类名后 +12 的包围盒（4×int32，0.01mm），
  并用幅面校验排除错位误读；近似方形 3~12mm 判为 Pb 标志。
- 写入模板的元素是 `{"type":"symbol","text":"pb-free","x":…,"y":…,"w":…,"h":…}`，
  标志由 `Rendering/Symbols.cs` 按归一化坐标绘制（圆环 4.2% / 宋体粗体字母 61.5%×55.5% / 45° 斜杠 4.6%，斜杠两端顶进圆环），
  内部 4 倍超采样，56px（7mm@203dpi）下细线不断，打印输出 1bpp 点阵。
- 模板编辑器工具栏有 **「+ Pb 标志」**，一键插入到标签右下部。
- 已按实测坐标补入 `ux2115 / ux3320_t / ux3370_b0 / ux5176s / ux5171u`；
  三个 TIA 模板的原 `.lsd` 没有图片对象，故未插入（需要时点按钮即可）。

矢量资产：`Assets/pb-free.svg`（同源导出）、`Assets/pb-free.png`（300px 位图）。
取证与实现细节见 `docs/Pb无铅标志识别.md`。

## 登录与退出

- **记住密码**：登录界面勾选「记住密码」后，密码经 Windows DPAPI（当前用户）加密存入 `config.json`，下次自动回填；取消勾选立即清除。同一机器、同一 Windows 用户才能解密，换机/换用户需重新输入。首次改密后若开着记住密码，会自动同步为新密码。
- **退出确认**：点击主窗口右上角关闭（或 Alt+F4）会弹出「确定要退出 UX_LabelShop 吗」确认框，避免误关丢失未打印清单。
- **退出登录确认**：点右上角「退出登录」同样会弹「确定要退出登录吗？退出后需要重新输入账号密码」确认框（默认焦点在「取消」），确认后才回到登录窗；退出登录不退出程序，也不丢当前清单。
- **主界面最大化**：登录成功后主窗口直接以最大化打开（`WindowState="Maximized"`）——扫码工位屏幕小，避免每次手动拉大；点还原后即按 1180×760 显示。
- **未保存修改确认**：模板编辑器、扫码规则窗口在关闭（右上角 × / Alt+F4 / 关闭按钮）时，如果当前内容相对上次保存有改动，弹「当前…有未保存的修改，关闭后会丢失」确认框，默认焦点在「取消」，取消则不关闭。
  判定用整份表单 / 模板 JSON 的状态快照比较，所以**改动后撤销回原状不会误报**；保存成功或变量子表更新后会刷新基线。自检模式（`App.IsSelfTest`）跳过弹框，避免离屏截图卡住。

## 打印到 PDF / 虚拟打印机

- 选「Microsoft Print to PDF」等虚拟打印机时，驱动会忽略自定义纸型而用 A4，并把大图切成数条横向 band 写入 PDF——**这是驱动行为，标签内容完整**（自检按「最大宽度 + 各 band 高度之和」核对，确认无放大/裁切）。
- 物理标签打印机（如 ZDesigner GK888t / Citizen CL-F3404）按模板真实尺寸出纸，无此问题。

## 已知事项

1. **首次连接约 10 秒**：服务器对新建 TCP 连接做反向 DNS 查询；登录窗已做后台预热，实际体感快很多。若可让 DBA 开启 `skip-name-resolve` 可彻底消除。
2. **真机打印未验收**：开发机无 Citizen CL-F3404 驱动，当前用「导出 PNG」+「打印到 PDF」模式验证（像素级比对与纸型校验均通过）；现场需验证纸型/浓度/走纸。
3. **扫码规则自动生成是初版**：新建模板会生成一条按变量顺序的默认规则（默认禁用），需在「扫码规则」中校准分隔符/marker/段映射后启用。
4. **`.lsd` 导入按实测包围盒重建版面**：导入会实测幅面、变量名表、对象包围盒，
   并按「输入数据：」对象记录锚点严格提取每个文本对象的**静态标签**（如「PO#:」「Date Code:」）
   与**上次输入的样例值**（如 `UX5176S` / `WX-260629-01`）。全文件扫描「长度前缀 + GBK」
   会把压缩块/位图误读成乱码，所以只在锚点段内用严格 GBK（非法字节直接丢弃）解码。
   - **正文**：按 y 容差 0.6mm 合并同一行的「标签框 + 值框」，左栏统一 x / 右边界
     （避免个别 0.85mm 窄框把整行字压小）；静态标签按行业通用视觉行序
     （西文 `PO# → Part No → Package → Date Code → Lot No → Q'TY → BIN`；
     中文 `订单号 → 产品型号 → 批号 → LOT ID → 片号 → 编号 → 数量 → DATE CODE → BIN`）
     均匀铺在实测首末行之间，补齐漏记行且不越界。`Date Code` 与 `DATE CODE` 分属两套版式，
     大小写敏感。
   - **标签 → 变量**：用候选 key 列表按「当前模板实际存在且未占用」挑选，兼容 TIA
     （`order/partno/batch…`）与 UX51xx（`track3/partno3/package3…`）两套命名体系；
     `Part No.:` / `Lot No.:` / `Bin:` / `Tracking NO.:` 等变体先规范化再匹配。
   - **样例值**：按标签语义认领（形态规则，如 `WX-…` → PO#、`QFN4*4-28L` → Package、
     `S7T405` → Lot No、`C2Fx2X8` → 批号、`N41474.1` → LOT ID），回填到变量 `sample`；
     **未被认领的值**用于右栏独立文字（`5176` / `S02T4H1` / `MSL:3`），按框宽就近匹配；
     `pcs` 作为数量单位附在 Q'TY 行后。
   - **多二维码**：按 y 顺序依次绑 `qr1`/`qr2`；若变量表声明了 2 个二维码但 `.lsd`
     只记录了 1 个包围盒（如 UX5176S），按首个二维码的 x/边长在幅面下方补位。
   - 条码 / 二维码 / 边框 / Pb 标志均用实测坐标；字号取框高的 0.9 倍，
     中文标签用粗体、纯西文标签保持常规字重。
   - 仍是 best-effort：对象样式（字体粗细、条码参数）封装在压缩块里无法逐字节还原，
     **文字与变量的对应关系、字体细节请按实物在编辑器中核对微调**。
   - `.lsd` 不记录 dpi，默认按 203 导入，可在对话框改 300。
   - 自检：`UXLabelshop.exe lsdtest [样本目录]`（10 个真实样本，100 项全通过）；
     `UXLabelshop.exe lsddump <文件路径>` 输出解析结果、全部元素与变量样例，
     并渲染 `logs/lsddump.png` 供与原版 LabelShop 截图比对。
5. **发布前先关掉正在运行的客户端**：exe 被占用时 `dotnet publish` 会以 `MSB4018` 失败，结束进程后重发即可。
